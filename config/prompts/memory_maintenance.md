## 保守アクションの判定基準

以下の4つのアクションのいずれかを提案してください。根拠が明確でない場合は絶対に提案を作成せず、`no_action` にしてください。

1. **merge** (マージ)
   - 矛盾しない重複や、お互いを補完し合う記憶が複数ある場合、それらを代表する1件（正本ID：`main_id`）に統合します。
   - `main_id` は必ず提示されたメモリIDのいずれかでなければなりません。
   - 吸収される側のメモリID（`absorbed_ids`）をリストで指定してください。
   - 正本・吸収側はすべて承認済み（statusがapproved）でなければなりません。
   - 統合後の本文（`integrated_content`）を日本語で自然かつ簡潔に作成してください。

2. **correct** (矛盾訂正)
   - 相互に矛盾する記憶が複数あり、明確な事実や時間的前後関係、エビデンス（証拠）に基づいてどちらかが「正しい」と確定できる場合、正しい方を正本ID（`main_id`）として残し、矛盾しているもう一方を `absorbed_ids` に指定します。
   - どちらが正しいかの根拠が十分に不足している場合は、絶対に提案せず `no_action` としてください。
   - 訂正後の確定本文（`integrated_content`）を作成してください。

3. **expire** (失効)
   - 期限（`valid_until` や `review_due_at`）が切れている、または最新のエビデンス（`observed_at`）の日付が基準日（${base_date}）より180日以上前であり、すでに古くて役に立たない・不要になったと明確に判断できるメモリがある場合、その1件を失効（`expired`）状態に移行することを提案します。
   - 古いだけで安定している嗜好や設定（明確な時間依存性のないもの）は、単に古いという理由だけで自動失効させず、不要になった明確な兆候（別の新しい活動やコメントなど）がある場合のみ提案してください。
   - 対象IDを `main_id` に設定し、`absorbed_ids` は空のリスト、`integrated_content` はnullまたは省略します。

4. **no_action** (現状維持)
   - 変更や統合、失効の必要がない（十分に有効で矛盾のない独立した記憶である）場合。

---

## 出力フォーマット

出力は必ず以下の構造のJSON配列（Proposals）のみにしてください。
余計な解説、前置き、後書き、およびマークダウンブロックなどは一切不要です。
指定するメモリIDは、必ず入力として与えられた実在のIDのみを使用してください。

### 制約
- 同一の提案内で複数のメモリIDが重複して出現してはなりません（例: `main_id` が `absorbed_ids` に含まれてはならない）。
- 1つのメモリIDが、複数の提案で重複して対象（`main_id` または `absorbed_ids` の中）に現れてはなりません。

```json
[
  {
    "action": "merge | correct | expire | no_action",
    "main_id": "正本メモリID、または失効させるメモリID",
    "absorbed_ids": ["吸収されるメモリID群（actionがmergeまたはcorrectの場合のみ必須。それ以外は空配列）"],
    "reason": "提案の根拠（簡潔な日本語）",
    "integrated_content": "統合・訂正後の本文（actionがmergeまたはcorrectの場合のみ必須。それ以外はnull）"
  }
]
```
