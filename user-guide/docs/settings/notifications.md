# 通知基盤 (Web Push / LINE)

Obsidian AI Hub では、要対応イベントおよび処理失敗イベントをリアルタイムに認知するための通知基盤を備えています。

## チャネルと対応イベント

- **初期チャネル**: Web Push（ブラウザ標準）および LINE（LINE Messaging API）
- **対象カテゴリ**:
  - **要対応 (action_required)**: HITL確認、Task承認・再承認待ち、Workflow承認・attention待ち、Agent/Coding質問（ask_user）、Planner提案、リサーチ提案
  - **失敗系 (failure)**: failed、interrupted、Taskのincomplete
- **対象外**: 開始・成功・キャンセルイベントは通知されません。

## 環境設定 (`.env`)

Web Push および LINE 送信に必要な環境変数を指定します。

```env
# Web Push VAPID 鍵設定
WEB_PUSH_VAPID_PUBLIC_KEY=your_vapid_public_key
WEB_PUSH_VAPID_PRIVATE_KEY=your_vapid_private_key
WEB_PUSH_VAPID_SUBJECT=mailto:admin@example.com

# LINE 通知設定（LINE Messaging API）
LINE_MESSAGING_TOKEN=your_line_channel_access_token
LINE_TARGET_ID=your_line_user_id

# 外部リンクの基底 URL（通知の深いリンクに使用）
OBSIDIAN_AI_HUB_WEB_URL=https://aihub.example.com
```

## 設定画面での有効化手順

すべての通知チャネルは初期状態で **オフ** になっています。

1. **設定画面** (`/settings`) へアクセスします。
2. **Web Push 通知**:
   - 「この端末でWeb Pushを購読」ボタンをクリックします。
   - ブラウザの通知許可ダイアログで「許可」を選択します。
   - 「要対応通知」および「失敗系通知」のチェックボックスで配信カテゴリを選択します。
3. **LINE 通知**:
   - 「LINE通知 有効化」のスイッチをオンにします。
   - 「要対応通知」および「失敗系通知」のチェックボックスで配信カテゴリを選択します。

## 通知受信箱 (`/notifications`)

発生したすべての通知イベントは、外部チャネルへの配信可否に関わらず永続的な「通知受信箱」として SQLite に保存されます。

- **サイドバー導線と未読バッジ**:
  サイドバーの「通知」導線には、要対応および失敗通知の未読合計件数がバッジとして表示されます。
- **絞り込みとページネーション**:
  - 状態絞り込み: 「すべて」「未読のみ」
  - 種別絞り込み: 「全種別」「要対応」「失敗」
  - ページ送り機能による過去履歴の確認
- **既読化と対象画面遷移**:
  - 通知一覧から項目をクリックして詳細を開くと、自動的に既読化されます。
  - 該当する対象画面（HITL、タスク、ワークフロー等）へ移動するには、詳細画面内の「対象画面を開く」深いリンクボタンから明示的に操作します。
- **履歴の不変性**:
  - 通知の本文・深いリンク・配信結果は発生時点の不変スナップショットとして保持されます。
  - 対象タスクやワークフローの後続完了・失敗によって、過去通知の既読状態や表示内容が変更されることはありません。

## チャネル別配信結果と閲覧保証の意味

各通知に対して、外部チャネル（LINE / Web Push）への配信試行結果が記録・表示されます。

- **表示区分**:
  - **未試行・処理中**: 配信処理がまだ開始前、または外部 API の結果待ちです。処理中のまま停止した場合は、次に記録できた時点で「結果不明」として扱います。
  - **意図的スキップ**: チャネルまたはカテゴリが無効、必要な設定がない、Web Push の有効な購読端末がない場合です。理由コードも履歴に残ります。
  - **API受理 / 一部受理**: LINE API または Push サービスが受理した結果です。Web Push は対象端末ごとの集計も表示します。
  - **失敗 / 結果不明**: 安全な理由コードと状態の確定時刻を表示します。「結果不明」は送信中の例外・停止により、外部サービスが受理したかを確認できない状態です。
- **閲覧保証と再送方針**:
  - 配信結果の「成功」は **「外部チャネル（LINE API や Push サービス）への正常受理」** を意味し、ユーザーによる実際の端末閲覧を保証するものではありません。
  - 配信はベストエフォートで **1度だけ** 試行されます。外部 API のエラーや配信失敗が発生した場合でも、受信箱に未読通知と失敗結果が残りますが、自動再送・手動再送は行われません。
