# Web AI エージェント 今後のロードマップ

v1（エージェント管理・会話・ツール境界）と、その後の UX 基盤（モバイル1ペイン、下書き保存、
入力欄2段化、ピン留め、横断検索、`/` コマンド、会話タイトル自動生成）は実装済み。
実装済み項目の詳細は `ai_wiki/10-Decisions-Web.md` / `ai_wiki/10-Decisions-Architecture.md` を正とする。

本書は**未実装の今後の候補**のみを扱う。実装の確約ではなく、目的・着手条件・依存関係を示す。

## 未実装の候補

### 1. `@` でコンテキスト参照（Vault ファイル・人物・プロジェクト）

- **背景**: 現在は「Vault の〇〇ノートを見て」と自然文で頼むしかなく、LLM が見落としやすい。
- **案**: `@` で autocomplete を開き、`@vault:相対パス` / `@person:人物名` / `@project:プロジェクト名`
  のプレースホルダを挿入する。LLM には通常テキストとして渡し、実体はツールで参照させる。
- **依存・着手条件**: 検索ソースとして既存 `/api/v1/vault-search`・`/api/v1/people` を再利用する。
  プロジェクト一覧 API が無ければ新設が必要（要確認）。`/` コマンドパレットの実装パターンを踏襲できる。
- **見込**: 2-3 日。読取り専用 UI で低リスク。

### 2. LLM が参照した外部情報へのリンク表示

- **背景**: `memory_search` / `vault_search` / `web_search` の結果を「LLM がこの情報を見て答えた」と
  UI で示したい。透明性・信頼性の向上。
- **案**: runtime が `tool_call_end` に `metadata`（source_paths / memory_ids / urls）を付与し、
  フロントが該当ツール結果に `Source:` リンクを描画する。
- **依存・着手条件**: 検索結果には既に `metadata` が含まれるため、抽出と描画の追加が主。SSE 契約の
  後方互換な拡張として実装できる。
- **見込**: ~2 日。読取り・UI のみ。

### 3. 会話履歴の要約と Vault 保存

- **背景**: 長くなったセッションを要約して Vault に残したい。既存のデイリーサマリー（1 日粒度）とは
  粒度が異なり（1 セッション）、共存価値はある。
- **案**: `POST /api/v1/agent-sessions/{id}/summarize-to-vault` で LLM 要約 → Vault ノートへ書出し。
- **依存・着手条件**: 自動書出しか HITL 確認かを先に決める（Vault への書込みを伴うため、既存 HITL /
  `vault_write_file` の承認方針との整合が必要）。
- **見込**: 2-3 日。

### 4. 書込み提案のチャット内編集と、承認後の会話自動再開

- **背景**: 予定・リマインダーの提案は現在 HITL 画面での承認のみ。会話内で編集・承認し、承認後に
  同じ会話を再開できると導線が短くなる。
- **依存・着手条件**: 既存の書込み提案 HITL と `ask_user` の会話再開機構を接続する設計が必要。
  外部書込みの承認境界は既存 Plan / HITL を維持する。

### 5. 予定・リマインダーの更新・削除・完了

- **背景**: エージェントのカレンダー/リマインダーツールは read と create proposal のみ。
- **依存・着手条件**: 更新・削除・完了には安定した対象識別子と HITL 承認設計が前提
  （`ai_wiki/10-Decisions-Architecture.md`「既存の `add_calendar_event` / `add_reminder` は作成専用…」）。

### 6. ユーザー定義の外部ツール／MCP

- **背景**: エージェントのツールを外部サービスへ広げたい。
- **依存・着手条件**: 権限・監査・ネットワーク境界を別途設計してから導入する。Python プラグイン機構
  （`ai_wiki/10-Decisions-Architecture.md`）は実装済みだが MCP は未対応。
