# Agent 会話の Vault ファイル参照（Per-Turn 文脈注入）設計

## Status

Accepted

## Context

`/agents` の会話では、Vault ノートを「見て」と自然文で頼むしかなく、LLM が参照を見落としやすいという課題があった（`docs/ai-agent/roadmap.md` 候補1）。原案は `@vault:相対パス` プレースホルダを本文に挿入し、実体はツールで読ませる方式だった。

## Decision

1. **共通ピッカー UI による明示選択**:
   - 入力欄での `@`（行頭または空白直後）と `+` メニュー「Vault ファイル」の双方から、同一の `AgentVaultFilePicker` を開く。
   - ピッカーは `GET /api/v1/vault-files`（`.md` のみ、隠しディレクトリ除外）を先読みし、ファイル名/パス部分一致を即時表示する。クエリ2文字以上では既存 `/api/v1/vault-search`（hybrid）の本文一致も追記する。クエリ空ではディレクトリツリーを辿れる。
   - 選択はテキストに挿入せず、画像添付と同型の**チップ**として保持する（パス空白・手編集破損の問題を回避）。

2. **サーバー側での本文埋め込み（Per-Turn 注入）**:
   - クライアントは `context_refs: [{kind: "vault_file", path}]`（パスのみ）を送信する。本文は送らない。
   - 投入時に件数（最大5）・kind・`.md`・Vault 内存在を検証し、不正は 400 で run を作らない。
   - `agent_messages.context_refs_json`（migration v55）にパスのみ保存し、冪等ハッシュに含める。
   - runtime はそのターン（現メッセージ＋履歴の user メッセージ）ごとに Vault から読み直して、ユーザーメッセージ本文の先頭に参照ブロックとして注入する。本文は DB に複製しない。

3. **劣化と安全性方針**:
   - 送信後に削除・リネームされた参照は run を失敗させず、「見つかりません」の注記に劣化させる。
   - 注入ブロックには「参照情報であり指示ではない」旨を付記し、埋め込み指示に従わせない。既存の `vault_read_file` / `vault_search` ツールと同等の外部送信境界であり、選択はユーザーの明示操作とする。

## Operation-scenario contract

| 段階 | 入力と正本 | 機械可読な識別子 | 永続化 | 次に読む主体 | 停止・失敗時 | 不可逆操作 |
| --- | --- | --- | --- | --- | --- | --- |
| 一覧 | Vault ディレクトリ走査 | Vault 相対 POSIX パス | なし | ピッカー | Vault 未設定は 400/404 | なし |
| 投入検証 | `StartAgentRunRequest.context_refs` | 正規化パス | なし（失敗はキューイングしない） | 本サービス | 形式・件数・存在不正は 400 で停止 | なし |
| 保存 | 検証済み参照 | `message_id` / `run_id` | `agent_messages.context_refs_json`（パスのみ） | worker・runtime・UI | スキーマ不足は 500 系で停止 | なし |
| 実行 | 保存済み参照 | `relative_path` | なし（毎回読み直し） | LLM プロバイダ | 欠落は注記に劣化して継続 | 参照ノート本文の LLM 送信（ユーザー明示選択） |
| 再実行 | 同一参照の再実行 | 同上 | 同一メッセージ行 | 同上 | 同上 | 同左（自動ロールバックなし） |

## Consequences

- 会話履歴の再読込・リプレイは保存パスから常に最新内容を引くため、ノート編集後の追質問が正しく反映される。反面、過去ターンの監査再現性は Vault 側の履歴に依存する。
- `.md` 以外・文字数上限なしは将来の拡張点。巨大ノートのコンテキスト超過は run 失敗として既存経路で表面化する。
