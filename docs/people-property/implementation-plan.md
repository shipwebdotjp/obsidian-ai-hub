# 人物属性 v1 実装計画

関連文書: [仕様書](specification.md) / [作業チェックリスト](todo.md) / [v2 以降ロードマップ](v2_roadmap.md)

実装は2フェーズに分ける。各フェーズ完了時点でDB整合性と既存人物機能の回帰を確認する。

## Phase 1 — 属性モデル、DB専用管理、統合整合性

目的は、Vaultに依存せずに型付き・期間付きの属性を安全に保存・管理できる基盤を完成させること。

- `database.py` に属性定義、選択肢、属性名/値alias、型別属性値のマイグレーションを追加する。実装開始時に最新 `user_version` を再確認し、人物・定義・選択肢の FK と削除伝播を設定する。
- 属性値は型別列を用い、将来の検索を前提に定義 ID + 値列 + 期間のインデックスを作る。JSON blob を検索用の唯一の保存形式にしない。
- `web/schemas.py` に定義、選択肢、属性値、削除影響、統合プレビューの DTO とバリデーションを追加する。
- `web/services/` に属性定義 CRUD、DB専用値 CRUD、型検証、期間重複検証、選択肢alias正規化を実装する。既存の人物サービスを薄いルート層に保ち、属性ロジックは専用サービスへ置く。
- 属性定義削除、人物削除、手動人物統合へ属性値の削除/移管を接続する。統合はプレビューと実行直前で競合を再検証し、部分移管を残さない。
- 属性定義・人物属性 API を Bearer 認証つきで公開する。Vault正本値への書込みは拒否する。
- 人物画面に「属性定義」管理と人物詳細の属性セクションを追加する。DB専用属性は編集可能、Vault正本属性は未同期/編集案内として扱う。
- API・サービス・マイグレーション・統合・フロントエンドの focused unit tests を追加する。`PersonDetail` と `people_get` が変わらない回帰テストを含める。

完了条件: 定義作成からDB専用値の登録・期間検証・表示・削除・人物統合までが一貫して動き、既存の人物同定・関係・削除機能が回帰しない。

## Phase 2 — Vault正本投影、同期レポート、運用仕上げ

目的は、既存の人物同期へ属性投影を安全に組み込み、Vault由来値とDB専用値を確実に分離すること。

- `utils/people_loader.py` を拡張し、既存の人物同定用 frontmatter 検証を維持したまま、定義済みVault正本属性を読めるようにする。
- スカラー、スカラー配列、`value` レコード、配列内の混在を型に応じて解析する。属性キーaliasと選択肢値aliasを正規化し、未知キーは無視する。
- `people_sync/sync.py` に属性投影を接続する。正常属性は全置換、欠落キーは削除、不正属性は既存投影保持＋属性単位レポートとする。DB専用属性と人物関係には触れない。
- Vault正本値を含む人物統合で、Phase 1の共通属性移管・競合検査を利用する。自動統合の競合は同期全体ではなく当該統合をスキップして報告する。
- Sync API/CLI と Vault入力レポートのスキーマ・UIを拡張し、属性の同期件数、不正な人物・属性、原因を表示する。
- `ai_wiki/10-Decisions-People.md` に、人物同定と属性の正本境界を分けるADRを追記する。必要な用語を用語集へ追加する。
- Vault同期の成功、不在値削除、型不正時の投影維持、alias、混在配列、DB専用値不変、自動統合競合をテストする。対象画面を手動確認する。

完了条件: Vaultの属性編集が手動同期で正しく投影され、不正入力が局所的に可視化・隔離され、DB専用値が同期で失われない。

## リリース前確認

- DB書込みテストは必ず `uv run pytest tests/` で実行し、本番DBを使わない。
- 影響範囲のPythonテスト、フロントエンド unit tests、TypeScript型検査を実行する。
- 人物画面、定義削除確認、Vault同期レポートを手動確認する。ブラウザE2Eは追加・通常実行しない。
- `git diff --check` と `git status --short` で意図しない変更を確認する。
