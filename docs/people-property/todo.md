## Phase 1 — 属性モデル、DB専用管理、統合整合性

- [ ] 実装開始時点の最新DB migration番号を確認する。
- [ ] 属性定義・選択肢・alias・型別属性値のテーブルと FK を追加する。
- [ ] 型別値・期間の検索用インデックスを追加する。
- [ ] 属性定義、選択肢、属性値、削除影響、統合影響のスキーマを追加する。
- [ ] 属性定義 CRUD と不変フィールドの拒否を実装する。
- [ ] DB専用属性値 CRUD、型検証、選択肢alias解決、期間・単数制約を実装する。
- [ ] 属性定義削除時の全属性値削除と影響件数返却を実装する。
- [ ] 人物削除の結果へ属性値削除件数を追加する。
- [ ] 人物統合プレビュー・実行へ属性移管、重複一本化、競合拒否を追加する。
- [ ] 属性定義・人物属性 API を Bearer 認証つきで追加する。
- [ ] 人物画面へ属性定義管理、DB専用値編集、Vault正本値の読取専用表示を追加する。
- [ ] Phase 1のDB/API/サービス/統合/フロントエンドテストを追加する。
- [ ] `PersonDetail` と `people_get` が変わらないことを回帰確認する。

## Phase 2 — Vault正本投影、同期レポート、運用仕上げ

- [ ] loaderが定義済みVault正本属性を取得できるようにする。
- [ ] スカラー、複数スカラー、値レコード、混在配列を解析・検証する。
- [ ] 属性名aliasと選択肢値aliasのVault解決を実装する。
- [ ] 同期へ正常値の全置換、欠落値の削除、不正属性の保留を追加する。
- [ ] 属性単位のVault入力レポートと同期件数をAPI/UIへ追加する。
- [ ] DB専用属性と人物関係が同期で不変であることを保証する。
- [ ] 自動人物統合へ属性競合のスキップ・レポートを接続する。
- [ ] Peopleの決定記録と用語集を更新する。
- [ ] Vault同期ケースと既存人物同期の回帰テストを追加・実行する。
- [ ] 人物属性画面とVault入力レポートを手動確認する。
