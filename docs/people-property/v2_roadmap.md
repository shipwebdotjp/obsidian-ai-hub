# 人物属性 v2 以降ロードマップ

関連文書: [仕様書](specification.md) / [実装計画](implementation-plan.md) / [作業チェックリスト](todo.md)

v1の型付き値・Vault正本投影を安定基盤とし、正本境界と既存値を壊さない順に機能を追加する。

## v3 — 部分日付・期間精度の基盤（前提フェーズ・実装済み）

- **偽の完全日付に変換しない時間表現**: date 属性値および valid_from / valid_until で YYYY、YYYY-MM、YYYY-MM-DD の精度付き日付を受理・返却する。
- **導出境界による統一判定**: DBに元の精度付き文字列表現を保持しつつ、検索・単数属性・人物統合・Vault同期の期間重複判定用に下限／上限日（value_date_min/max, valid_from_min, valid_until_max）を保持・利用する。
- **時間条件検索プリミティブ**: サービス層に時間範囲の重複判定（`matches_temporal_condition`）を用意し、検索条件と可能日付範囲が重なれば候補とし、結果には元の精度付き文字列を返却する。

## v2 — 属性検索と安全な定義移行

- v3で整備した時間基盤（導出境界列）を利用し、属性定義、型別値、期間を条件にした人物一覧の検索・絞り込みを追加する。
- 型、単複、正本種別を変更する専用移行を追加する。変換プレビュー、変換不能値、期間競合、ロールバック、Vault既存記述の扱いを明示する。
- 属性定義のアーカイブまたは安全な置換を検討する。

## 後続フェーズ — 追加型・概算値・変更履歴

- **追加型と概算値**: URL、人物参照、構造化値、および「頃・約・不明範囲」などの概算値表現を追加する。
- **変更履歴と監査**: 属性値・定義の変更履歴を append-only イベントモデルで管理し、復元は補償イベントとして扱う（ADR 記録済み）。

## v4 — Vault支援とAI連携

- 属性定義のVaultテンプレート生成、差分プレビュー付きのVault書き戻し、競合解決を追加する。DB専用属性を暗黙に書き戻さない。
- **AIへの全属性公開 (v4初期版・実装済み)**: `people_get` を有効化した全エージェントへ、人物の全属性値（DB/Vault、期間付き履歴、複数値を含む）を公開する。属性単位アクセス制御や件数上限は設けず、既存の agent run ツール呼出履歴を監査に利用する。
- **将来の限定公開制御 (未設計)**: 将来の必要性に応じて、属性単位・エージェント単位のアクセス制御、件数上限、専用監査ログなどの限定公開モデルを設計・導入する。
- ノートからの属性候補抽出を、根拠・信頼度・ユーザー承認つきで追加する。AIはVault/DBの正本を自動上書きしない。
- **日次要約からの人物属性変更候補抽出（実装済み）**: 日次要約で解決された確定人物に対し、DB専用属性の変更候補（create/update/delete）を抽出し、HITL承認（`daily_person_changes`）を経て個別トランザクションで安全に正本へ反映する。承認前のDB自動上書きは行わない。

## 着手時の原則

- 型・正本・時間表現・履歴・AI公開は変更コストと横断影響が大きい。開始前に移行計画とADR要否を確認する。
- Vault由来値とDB専用値の境界を曖昧にしない。双方向同期は差分・競合・承認フローを定義してから導入する。
- 検索・AI機能は、v1の型別列と正規化済み選択肢を利用し、表示文字列への曖昧検索を唯一の正本にしない。
