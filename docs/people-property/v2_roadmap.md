# 人物属性 v2 以降ロードマップ

関連文書: [仕様書](specification.md) / [実装計画](implementation-plan.md) / [作業チェックリスト](todo.md)

v1の型付き値・Vault正本投影を安定基盤とし、人物属性を横断して検索・比較・点検する日常利用を最優先に、正本境界と既存値を壊さない順に機能を追加する。

## 実装済みの基盤

- **部分日付・期間精度（v3）**: date 属性値および valid_from / valid_until で `YYYY`、`YYYY-MM`、`YYYY-MM-DD` の精度付き日付を受理・返却する。DB に元の精度付き文字列表現を保持しつつ、検索・単数属性・人物統合・Vault 同期の期間重複判定には下限／上限日（`value_date_min` / `value_date_max`、`valid_from_min` / `valid_until_max`）を利用する。
- **属性条件検索 API（v2）**: `POST /api/v1/people/search` で、属性定義、型別値、期間、人物名による人物検索と絞り込みを提供する。時間条件は `matches_temporal_condition` により可能日付範囲の重なりで判定し、結果には元の精度付き文字列を返す。
- **AI への全属性公開（v4初期版）**: `people_get` を有効化した全エージェントへ、人物の全属性値（DB/Vault、期間付き履歴、複数値を含む）を公開する。属性単位アクセス制御や件数上限は設けず、既存の agent run ツール呼出履歴を監査に利用する。
- **日次要約からの人物属性変更候補抽出**: 日次要約で解決された確定人物に対し、DB 専用属性の変更候補（create/update/delete）を抽出し、HITL承認（`daily_person_changes`）を経て個別トランザクションで安全に正本へ反映する。承認前の DB 自動上書きは行わない。

## 実装順

### v2 — 人物属性エクスプローラー

既存の属性検索 API を、日常的に使える人物の発見・比較画面へつなぐ。

- **条件検索 UI**: 型に応じた条件、複数条件の AND、人物名、期間条件で人物を絞り込めるようにする。
- **検索結果の比較表示**: 検索に一致した属性値を人物ごとに横並びで比較し、人物詳細へ遷移できるようにする。初期版は既存検索結果の `matched_properties` とページングを利用する。
- 検索 API の契約は変更せず、表示文字列への曖昧検索を唯一の正本にしない。

### v2.1 — 属性カタログ・登録状況の可視化

属性定義ごとの利用状況と、見直しが必要なデータを横断的に把握できるようにする。

- **属性カタログ**: 属性定義ごとに、登録人数、値の分布、未登録人物、Vault/DB の正本種別、同期エラーの有無を表示する。
- **見直し導線**: 未入力、期間不明、同期保留の属性を抽出し、該当する人物詳細へ遷移できるようにする。値の自動補完や自動修正は行わない。

### v3 — 属性履歴と安全な定義の進化

属性値の変遷を閲覧しながら、定義を安全に育てられるようにする。

- **属性履歴と時間軸**: 各人物の属性値を過去・現在・将来の有効期間に分けて時系列表示し、検索・比較画面から指定時点の値を確認できるようにする。部分日付と境界列を判定の唯一の基盤とする。
- **安全な定義移行**: 型、単複、正本種別を変更する専用移行、定義のアーカイブ、安全な置換を提供する。変換プレビュー、変換不能値、期間競合、Vault 既存記述、ロールバックを明示し、物理削除を日常的な定義整理の手段にしない。

### v4 — 表現力と変更履歴の拡張

検索・比較・履歴で一貫して扱える値の表現力と監査性を追加する。

- **追加型と概算値**: URL、人物参照、構造化値、および「頃・約・不明範囲」などの概算値表現を追加する。既存型・部分日付との移行方針を決定してから着手する。
- **変更履歴と監査**: 属性定義、選択肢、別名、属性値、Vault 同期の変更履歴を append-only イベントモデルで管理し、復元は補償イベントとして扱う（ADR 記録済み）。人物詳細と属性カタログから変更経緯を閲覧可能にする。

### v5 — AI による候補抽出の拡張

日次要約で実装済みの HITL 承認パターンを、他のノート由来属性へ安全に広げる。

- ノートからの属性候補抽出を、根拠、信頼度、既存値との差分、ユーザー承認つきで追加する。AI は Vault/DB の正本を自動上書きしない。

### v6 — AI 公開の限定制御

- 属性・エージェント・人物単位のアクセス制御、返却件数上限、専用アクセス監査を、必要性が明確になった時点で設計・導入する。
- 現行の `people_get` による全属性公開との互換性と移行を設計時に明記する。

### v7 — Vault 支援と承認付き書き戻し

- 属性定義の Vault テンプレート生成、差分プレビュー、明示承認、競合解決、失敗時の復旧手順を備えた書き戻しを提供する。DB 専用属性を暗黙に書き戻さない。

## 着手時の原則

- 型・正本・時間表現・履歴・AI公開は変更コストと横断影響が大きい。開始前に移行計画とADR要否を確認する。
- Vault由来値とDB専用値の境界を曖昧にしない。双方向同期は差分・競合・承認フローを定義してから導入する。
- 検索・AI機能は、v1の型別列と正規化済み選択肢を利用し、表示文字列への曖昧検索を唯一の正本にしない。
