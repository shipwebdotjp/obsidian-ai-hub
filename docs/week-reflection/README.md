# 週次リフレクションと Coach の方向性

## 目的

日曜夕方に週次ノートの下書きを見ながら一週間を軽く振り返り、翌週に意識したい小さな一歩を自分で選ぶ習慣をつくる。

AI の役割は、「次にやるべきこと」を自動で決めたり予定を埋めたりすることではない。日次ノートや週次下書きを材料に、Goal / Focus に関係する出来事を思い出すための問いと候補を出し、人が意味づけて採択できるよう支援することとする。

## 決定した方向性

### 自動プランナーはゼロ件を標準にする

自動プランナーは、何かを出すこと自体を目的にしない。明示的な依頼、期限、未完了の根拠がない限り、提案がゼロ件であることを正常とする。

活動ログや技術作業の記録だけから「次にやるべき作業」を推測して、カレンダーやリマインダーの候補にしない。作業の完了状態、重要度、予定化の妥当性は、ログだけでは確定できないためである。

### 週次下書きは Coach の Goal / Focus を視点として使う

既存の週次レビュー下書きに、現在の Coach の Goal / Focus を渡す。これにより、単なる活動の列挙ではなく、今週の出来事が自分の大切にしたい方向とどう関係したかを振り返れるようにする。

Goal / Focus は達成度を採点する基準ではない。出来事を見直すための視点であり、記録がない週や進展を感じない週も、そのまま扱う。

### Coach は週次チェックインの場にする

週次ノートの本文を正本とし、Coach には次を構造化して残す。

- Focus との関係
- 気づき・学び
- 次週に意識すること、または試す小さな一歩

標準のチェックインは軽くする。一言の振り返り、または「特になし」で完了できることを重視する。詳細な振り返りは、本人が必要と感じた週だけ行える任意の深掘りとする。

AI が次週の候補を示しても、それは提案に留める。Coach に残す内容、予定・リマインダーにする内容は、必ず人が採択する。

## 役割分担

| 場所 | 役割 |
| --- | --- |
| 週次ノート | 振り返り本文の正本。出来事、感情、背景を自由に残す。 |
| Coach | Goal / Focus との関係、学び、次週の意図を構造化して継続性を支える。 |
| AI | 事実を断定せず、思い出すための問い、関連しそうな出来事、次の小さな一歩の候補を示す。 |
| プランナー | 人が明示的に決めた、日時を置く価値のある予定・リマインダーを扱う。 |
| 人 | 意味づけ、優先順位、採択、予定化を決める。 |

## 段階的な進め方

### Phase 1: ノイズを止める

自動プランナーを「高確信の明示的な用件だけを扱う」方向へ縮める。ゼロ件を通常の結果として受け入れ、作業ログからの推測的な候補で注意を奪わないようにする。

実装済み（2026-10-30）: 候補は日次ノートの明示的な用件を `[E番号]` で引用したものだけを保存し、引用先を確認できない候補は捨てる。0件は成功として扱い、日付が過ぎた提案と作成から30日を超えた提案は自動で `expired` にする。判断の記録は [明示的な用件だけを提案する](../../ai_wiki/10-Decisions-Integrations.md#明示的な用件だけを提案する2026-10-30-追記)。

### Phase 2: 週次下書きに方向性を与える

既存の週次レビュー下書きに、現在の Goal / Focus を振り返りの視点として加える。日曜の通知、週次ノート、下書きという既存の習慣の入口は活かす。

実装済み（2026-10-30）: Coach の Goal（`status='active'`）と Focus（`status` が `active` または `paused`）を自動取得し、振り返りの視点として参照プロンプトに注入。Coach 情報が存在する場合は条件付き見出し `## Focus との関係` を含む6見出し形式として生成・検証し、情報がない・取得失敗時は従来の5見出し形式で生成・保存・送信する。判断の記録は [週次レビュー下書きへの Coach Goal / Focus 視点注入](../../ai_wiki/10-Decisions-Integrations.md#週次レビュー下書きへの-coach-goal--focus-視点注入phase-2)。

### Phase 3: 軽い週次チェックインをつなぐ

週次下書きを読んだ後、Coach で軽い対話を始められるようにする。まずは今週に関係があった Focus を一つだけ扱い、振り返りと次週の意図を本人が選べるようにする。

実装済み（2026-10-30）: 日曜17:30 の `--review-draft` 実行で、下書きの週次ノートへの保存に加えて週次チェックインの HITL Run（`coach_checkin_{ISO年}-W{週}`）を作成し、LINE へはチェックインへのリンクだけを通知する。下書き本文の LINE 送信は行わない。チェックインは自由記述2問（今週の様子＋来週試したいこと・任意）と4択（continue / narrow / change / pause）で構成し、回答は既存の週次 Reflection 登録経路に写像する。質問文は対象週の日次ノート・保存済み下書き・直近の `next_week_scope` を材料に生成し、生成失敗時は定型文にフォールバックする。回答期限は作成から7日間で、期限切れの必須質問がある Run は自動キャンセルされ Reflection は作られない。判断の記録は [週次チェックインをHITLの問いとして配信し、先週の一歩を参照する](../task-agent/adr/weekly-checkin-hitl-question.md)。

### Phase 4: 必要な週だけ深掘りする

軽いチェックインを妨げずに、複数 Focus の検討、難しかった理由の整理、学びの言語化、次週の範囲の具体化を行えるようにする。深さを毎週求めず、必要なときの選択肢として提供する。

## 意図的に行わないこと

- AI が活動ログからタスクを大量に自動生成すること
- AI が人の代わりに次週の予定やリマインダーを確定すること
- プロジェクトごとの詳細なタスク管理を、週次リフレクションの前提にすること
- 連続記録、達成率、未達の催促など、振り返りを圧力に変える仕組み
- すべての Goal / Focus を毎週必ず振り返らせること

この方向性は、実際に日曜のチェックインを続けながら見直す。まずは「週次ノートを開き、短く振り返る」ことが続くかを最優先にする。
